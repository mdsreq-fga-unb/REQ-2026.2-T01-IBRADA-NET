    8 REQUISITOS DE SOFTWARE

    8.1 Lista de Requisitos Funcionais

    • Requisitos Funcionais (RF)
    ID Nome Descrição
    RF01 Cadastrar projetos Permitir que os gestores do IBRADA possam cadastrar projetos de regularização ambiental de propriedades rurais, inclusão sócio-produtiva e assistência técnica e extensão de áreas rurais em um dashboard.
    RF02 Editar projetos Permitir que os gestores possam editar informações sobre os projetos do dashboard.
    RF03 Remover projetos Permitir que os gestores possam remover os projetos do dashboard.
    RF04 Exibir dashboard de impacto Disponibilizar um painel público que permite interação com o gestor e exibe indicadores de impacto dos projetos.
    RF05 Apresentar formulário de triagem Apresentar um formulário guiado com campos simplificados para identificar o tipo de solicitação e o perfil do usuário
    RF06 Visualizar catálogo de ecoturismo Permitir aos usuários visualizar o catálogo de experiências de ecoturismo, incluindo descrições, datas, disponibilidade de vagas e valores.
    RF07 Detalhar experiências Página detalhada de uma experiência com informações completas e com mecanismos simplificados de compartilhamento.
    RF08 Cadastrar clientes Permitir cadastro de novas contas para clientes interessados em reservas.
    RF09 Editar perfil de clientes Permitir que clientes possam editar seus dados pessoais registrados em suas contas.
    RF10 Realizar login de cliente Permitir que clientes cadastrados acessem o sistema mediante validação de credenciais, garantido limitação adequada a acesso de funcionalidades destinadas a gestores do sistema.
    RF11 Encerrar sessão de cliente Permitir que clientes encerrem sua sessão do sistema de forma segura.
    RF12 Realizar reserva de pacotes de ecoturismo Permitir que o usuário autenticado selecione uma experiência, realize a reserva visualizando resumo antes de checkout.
    RF13 Realizar pagamento Permitir que o usuário realize pagamento de pacotes de ecoturismo.
    RF14 Criar experiências de ecoturismo Oferecer um painel administrativo para a equipe do IBRADA criar experiências.
    RF15 Editar experiências de ecoturismo Oferecer um painel administrativo para a equipe do IBRADA editar experiências.
    RF16 Habilitar a disponibilidade dos produtos O gestor pode habilitar a inscrição nas experiências de ecoturismo
    RF17 Desabilitar a disponibilidade dos produtos O gestor pode desabilitar a inscrição nas experiências de ecoturismo
    RF18 Cadastrar oportunidades de voluntariado Permitir ao gestor cadastrar oportunidades de voluntariado, definindo habilidades requeridas, duração, disponibilidade e projeto associado
    RF19 Editar oportunidades de voluntariado Permitir ao gestor editar as informações das oportunidades de voluntariado registradas no sistema.
    RF20 Listar oportunidades de voluntariado Voluntários podem visualizar oportunidades abertas.
    RF21 Cadastrar perfil do voluntário Permitir que usuários se cadastrem como voluntários, informando suas habilidades, experiências, áreas de interesse e disponibilidade
    RF22 Editar perfil do voluntário Permitir que usuários cadastrados como voluntários possam editar suas informações do perfil.
    RF23 Candidatar voluntários Permitir que voluntários se candidatem à oportunidades de voluntariado abertas.
    RF24 Realizar login de voluntário Permitir que voluntários cadastrados acessem o sistema mediante validação de credenciais, garantido limitação adequada a acesso de funcionalidades destinadas a gestores do sistema.
    RF25 Encerrar sessão de voluntários Permitir que voluntários encerrem sua sessão do sistema de forma segura.
    RF26 Visualizar candidatos Permitir que gestores visualizem todos os candidatos em funil.
    RF27 Criar perfil de interesse de notificações Permitir que o usuários selecione preferências para receber notificações de novos projetos de interesse.
    RF28 Editar preferências de notificações Permitir que o usuário edite quais notificações deseja receber ou desativá-las.
    RF29 Exibir painel de gestão de notificações Permitir que o gestor visualize estatísticas e gerencie notificações enviadas.
    RF30 Realizar formulário de solicitação de parceria Fornecer um formulário simplificado para empresas externas enviarem solicitações de parceria, coletando informações.
    RF31 Gerenciar propostas de parceria Apresentar um painel centralizado para a equipe do IBRADA visualizar as solicitações recebidas
    RF32 Enviar resposta de solicitação Permitir que o gestor envie uma resposta formal automatizada à empresa via email.
    • Requisitos de Negócio (RN)
    ID Nome Descrição
    RN01 Indicadores de impacto Permitir que gestores atualizem indicadores de impacto para cada projeto.
    RN02 Filtro do dashboard de impacto Permitir filtragem do dashboard de impacto por área de atuação, status e período.
    RN03 Redirecionar para atendimento via WhatsApp Redirecionar o usuário para o WhatsApp do IBRADA, carregando uma mensagem pré-configurada correspondente às respostas fornecidas na triagem
    RN04 Encaminhamento para Departamentos Se a triagem identificar outro serviço, encaminhar solicitação para um departamento específico (roteamento interno).
    RN05 Filtros e busca de experiências Permitir que o usuário possa filtrar experiências por critérios.
    RN06 Pagamento via gateway externo Os pagamentos realizados no produto deverão utilizar um gateway externo via API e exibindo o status do pagamento.
    RN07 Detalhes de oportunidade Página com informações completas de uma oportunidade.
    RN08 Filtros de candidato Permitir que gestores filtrem candidatos por múltiplos critérios.
    RN09 Detalhes de Candidato Ao selecionar um candidato o sistema permite ver perfil completo.
    RN10 Notificações a candidato de voluntariado Enviar notificações por email automaticamente aos usuários cadastrados que correspondam aos interesses declarados em seus perfis
    RN11 Notificação novo projeto Notificar apoiador quando projeto novo na sua área é lançado.
    RN12 Detalhe de Solicitação Meio de visualizar informações completas de solicitação.

    8.2 Lista de Requisitos Não Funcionais

    ID Nome Descrição Classificação URPS+ CPs relacionada/transversais
    RNF01 Responsividade da interface A interface do sistema deve se adaptar a smartphones (320px–480px), tablets (481px–1024px) e desktops (acima de 1024px), garantindo legibilidade, usabilidade e ausência de quebra de layout em todos os tamanhos de tela. Usabilidade Transversal (todas as CPs)
    RNF02 Integridade transacional O banco de dados deve garantir a conformidade ACID (Atomicidade, Consistência, Isolamento, Durabilidade) nas transações de ecoturismo para impedir reservas duplicadas (overbooking) e inconsistências de vagas. Confiabilidade CP3
    RNF03 Desempenho do catálogo O tempo de carregamento das listagens de projetos e do catálogo de experiências de ecoturismo não deve ultrapassar 3 segundos em conexões de banda larga padrão. Performance CP1, CP3
    RNF04 Autenticação e autorização O sistema deve implementar controle de acesso baseado em papéis (RBAC - Role-Based Access Control), restringindo o acesso aos painéis de gerenciamento exclusivamente à equipe autorizada do IBRADA. + (Segurança) Transversal (CP1, CP3, CP4, CP6)
    RNF05 Integração Externa O módulo de pagamento deve se comunicar com a API do gateway de pagamento externo de forma assíncrona, tratando as respostas de webhook para atualizar o status das reservas. + (Interfaces) CP3
    RNF06 Escalabilidade sob demanda O sistema deve suportar até 200 usuários simultâneos ativos (navegando, reservando ou preenchendo formulários) sem degradação perceptível de desempenho. Performance / Suportabilidade CP1, CP3, CP5
    RNF07 Disponibilidade do sistema A plataforma deve estar disponível para acesso público (dashboard de projetos, catálogo de ecoturismo, formulários de triagem e parceria) de forma contínua, minimizando janelas de indisponibilidade. Confiabilidade Transversal (todas as CPs)
    RNF08 Proteção de dados pessoais (LGPD) O sistema deve armazenar e tratar dados sensíveis (como CPF e informações de contato) de voluntários e clientes de forma criptografada no banco de dados, e deve exibir e registrar o consentimento explícito do usuário no momento do cadastro. + (Legal/Segurança) CP3, CP4, CP6
    RNF09 Usabilidade do formulário de triagem O formulário de triagem inicial deve ser simples o suficiente para ser concluído por usuários com baixa familiaridade digital. Usabilidade CP2
    RNF10 Compatibilidade entre navegadores O sistema deve funcionar corretamente nos principais navegadores web utilizados pelo público-alvo (Chrome, Firefox, Safari e Edge), suportando a versão estável mais recente e imediatamente a versão anterior de cada navegador. Suportabilidade Transversal (todas as CPs)
