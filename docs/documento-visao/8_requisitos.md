# 8 REQUISITOS DE SOFTWARE

A apuração dos requisitos está descrita na [Disponibilização dos requisitos](../entrega-atividades/atividade1.md)

A classificação desses requisitos e a apuração da declaração se econtra na [atividade de declaração](../entrega-atividades/atividade5.md) 

## 8.1 Lista de Requisitos Funcionais

| ID | Nome | Descrição | Relação |
| --- | --- | --- | --- |
| <span id="rf01"></span>RF01 | Cadastrar projetos | Permitir que os gestores do IBRADA possam cadastrar projetos de regularização fundiária e ambiental de propriedades rurais, inclusão sócio-produtiva e assistência técnica e extensão de áreas rurais em um dashboard. | CP1 |
| <span id="rf02"></span>RF02 | Editar projetos | Permitir que os gestores possam editar informações sobre os projetos do dashboard. | CP1 |
| <span id="rf03"></span>RF03 | Remover projetos | Permitir que os gestores possam remover os projetos do dashboard. | CP1 |
| <span id="rf04"></span>RF04 | Exibir resultados e dados de impacto dos projetos | Permitir que visitantes visualizem, em um painel de acesso público, os indicadores de impacto dos projetos. | CP1 |
| <span id="rf05"></span>RF05 | Apresentar formulário de triagem | Permitir que o visitante (possível turista, apoiador ou usuário buscando regulamentação ambiental) preencha um formulário de triagem guiado com campos simplificados para identificar o tipo de solicitação e seu perfil, armazenando os dados no sistema e o encaminhando corretamente. | CP2 |
| <span id="rf06"></span>RF06 | Visualizar catálogo de ecoturismo | Permitir aos usuários visualizar o catálogo de experiências de ecoturismo, incluindo descrições, datas, disponibilidade de vagas e valores. | CP3 |
| <span id="rf07"></span>RF07 | Detalhar experiências | Permitir que o usuário visualize informações completas de uma experiência de ecoturismo selecionada. | CP3 |
| <span id="rf08"></span>RF08 | Cadastrar clientes | Permitir que os visitantes interessados em reservas se cadastrem em novas contas como clientes. | CP3 |
| <span id="rf09"></span>RF09 | Editar perfil de clientes | Permitir que clientes possam editar seus dados pessoais registrados em suas próprias contas. | CP3 |
| <span id="rf10"></span>RF10 | Realizar login de cliente | Permitir que clientes cadastrados acessem o sistema mediante validação de credenciais. | CP3 |
| <span id="rf11"></span>RF11 | Encerrar sessão de cliente | Permitir que clientes encerrem sua sessão ativa no sistema. | CP3 |
| <span id="rf12"></span>RF12 | Selecionar pacote de ecoturismo | Permitir que o cliente realize a reserva dos pacotes de ecoturismo selecionados. | CP3 |
| <span id="rf13"></span>RF13 | Confirmar reserva | Permitir que o cliente confirme a reserva antes do checkout. | CP3 |
| <span id="rf14"></span>RF14 | Pagar reserva | Permitir que o cliente realize pagamento de suas reservas de pacotes de ecoturismo. | CP3 |
| <span id="rf15"></span>RF15 | Cadastrar experiências de ecoturismo | Permitir à equipe do IBRADA cadastrar experiências de ecoturismo no sistema. | CP3 |
| <span id="rf16"></span>RF16 | Editar experiências de ecoturismo | Permitir à equipe do IBRADA editar experiências de ecoturismo no sistema. | CP3 |
| <span id="rf17"></span>RF17 | Alterar disponibilidade de experiência de ecoturismo | Permitir que o gestor marque uma experiência de ecoturismo como disponível ou indisponível para novas reservas. | CP3 |
| <span id="rf18"></span>RF18 | Cadastrar oportunidades de voluntariado | Permitir ao gestor cadastrar oportunidades de voluntariado, definindo habilidades requeridas, duração, disponibilidade e projeto associado. | CP4 |
| <span id="rf19"></span>RF19 | Editar oportunidades de voluntariado | Permitir ao gestor editar as informações das oportunidades de voluntariado registradas no sistema. | CP4 |
| <span id="rf20"></span>RF20 | Gerenciar papel de gestor | Permitir que um gestor cadastre outros membros da equipe do IBRADA como gestores, concedendo a eles acesso aos painéis do sistema. | CP4 |
| <span id="rf21"></span>RF21 | Listar oportunidades de voluntariado | Permitir que o voluntário consulte a lista de oportunidades de voluntariado abertas. | CP4 |
| <span id="rf22"></span>RF22 | Visualizar detalhes de oportunidade de voluntariado | Permitir que o voluntário visualize as informações detalhadas de uma oportunidade selecionada, incluindo habilidades requeridas, duração, disponibilidade e projeto associado. | CP4 |
| <span id="rf23"></span>RF23 | Cadastrar perfil do voluntário | Permitir que usuários se cadastrem como voluntários, informando suas habilidades, experiências, áreas de interesse e disponibilidade. | CP4 |
| <span id="rf24"></span>RF24 | Editar perfil do voluntário | Permitir que usuários cadastrados como voluntários possam editar suas informações do perfil. | CP4 |
| <span id="rf25"></span>RF25 | Candidatar-se a oportunidade | Permitir que o voluntário autenticado se candidate a uma oportunidade de voluntariado aberta. | CP4 |
| <span id="rf26"></span>RF26 | Realizar login de voluntário | Permitir que voluntários cadastrados acessem o sistema mediante validação de credenciais. | CP4 |
| <span id="rf27"></span>RF27 | Encerrar sessão de voluntários | Permitir que voluntários encerrem sua sessão ativa no sistema. | CP4 |
| <span id="rf28"></span>RF28 | Visualizar candidatos | Permitir que gestores visualizem todos os candidatos a uma oportunidade em funil. | CP4 |
| <span id="rf29"></span>RF29 | Registrar consentimento de uso de dados | Permitir que o usuário visualize o termo de consentimento (LGPD) no momento do cadastro e o aceite explicitamente, registrando data, hora e versão do termo aceito. | CP4 |
| <span id="rf30"></span>RF30 | Configurar preferências de notificação | Permitir que o usuário selecione, edite ou desative os alertas de projetos de seu interesse. | CP5 |
| <span id="rf31"></span>RF31 | Exibir estatísticas de alcance das notificações | Permitir que o gestor visualize estatísticas de alcance das notificações enviadas. | CP5 |
| <span id="rf32"></span>RF32 | Gerenciar envio de notificações | Permitir que o gestor gerencie notificações enviadas. | CP5 |
| <span id="rf33"></span>RF33 | Preencher solicitação de parceria | Permitir que um candidato a parceiro preencha um formulário simplificado para solicitação de parceria, coletando informações (data, tipo e área). | CP6 |
| <span id="rf34"></span>RF34 | Visualizar propostas de parceria | Apresentar um painel centralizado para a equipe do IBRADA visualizar as solicitações de parceria recebidas. | CP6 |
| <span id="rf35"></span>RF35 | Enviar resposta de solicitação de parceria | Permitir que o gestor escreva uma resposta à solicitação de parceria pelo sistema, que será enviada de forma automática por email para a empresa candidata. | CP6 |
| <span id="rf36"></span>RF36 | Compartilhar experiências | Permitir que o usuário compartilhe o conteúdo de uma experiência de ecoturismo selecionada, identificando corretamente a experiência compartilhada. | CP3 |

## 8.2 Lista de Regras de Negócio

| ID | Nome | Descrição | Relação |
| :--- | :--- | :--- | :---: |
| <span id="rn01"></span>RN01 | Redirecionar para atendimento via WhatsApp | Usuários devem ser redirecionados para o WhatsApp do IBRADA após responder uma triagem, carregando uma mensagem pré-configurada correspondente às respostas fornecidas na triagem. | CP2 |
| <span id="rn02"></span>RN02 | Encaminhamento para Departamentos | Se a triagem identificar outro serviço, encaminhar solicitação para um departamento específico, realizando o roteamento interno. | CP2 |
| <span id="rn03"></span>RN03 | Cadastro de email de usuário. | Cada email registrado pode ter apenas um usuário vinculado a ele. | CP3 |
| <span id="rn04"></span>RN04 | Pagamento via gateway externo | Os pagamentos realizados no produto deverão utilizar um gateway externo via API, exibindo o status do pagamento. | CP3 |
| <span id="rn05"></span>RN05 | Filtro de candidatos | O sistema de processo seletivo deve filtrar candidatos aptos a uma oportunidade de voluntariado através de um funil baseado em critérios informados durante o cadastro selecionados pelo gestor durante o cadastro da oportunidade (exemplos: aptidão física, conhecimento técnico, experiências poteriores, etc.). | CP4 |
| <span id="rn06"></span>RN06 | Notificações de oportunidades e projetos | Notificações devem ser enviadas por email de forma automática aos usuários cadastrados que correspondam aos interesses declarados em seus perfis. | CP5 |

## 8.3 Lista de Requisitos Não Funcionais

| ID | Nome | Descrição | Classificação URPS+ | Relação |
| --- | --- | --- | --- | --- |
| <span id="rnf01"></span>RNF01 | Responsividade da interface | A interface do sistema deve preservar a usabilidade e adaptar os componentes visuais para resoluções de desktops, laptops, tablets e dispositivos móveis (smartphones). | Usabilidade | Transversal (Todas as CPs) |
| <span id="rnf02"></span>RNF02 | Integridade transacional |O sistema deve garantir transações ACID e impedir reservas concorrentes para a mesma vaga, evitando overbooking.| Confiabilidade | CP3 |
| <span id="rnf03"></span>RNF03 | Desempenho do catálogo | As listagens de projetos e do catálogo de experiências devem carregar em até 3 segundos, em pelo menos 95% das medições, com conexão de 15 Mbps ou mais e com até 50 usuários simultâneos.| Performance | CP1, CP3 |
| <span id="rnf04"></span>RNF04 | Autenticação e autorização | O sistema deve negar acesso por padrão a usuários não autenticados ou sem papel de Gestor e registrar em log do sistema as tentativas de acesso não autorizado às rotas de gerenciamento, com data/hora e rota acessada. | Segurança | Transversal (CP1, CP3, CP4, CP6) |
| <span id="rnf05"></span>RNF05 | Integração Externa |O sistema deve receber as notificações de pagamento do provedor externo e atualizar o status da reserva correspondente, sem processá-las em duplicidade.|(+Interfaces/Confiabilidade)| CP3 |
| <span id="rnf06"></span>RNF06 | Capacidade e desempenho sob carga | O sistema deve suportar 200 usuários simultâneos ativos (navegando, reservando ou preenchendo formulários), com tempo de resposta ≤ 3s para 95% das requisições e taxa de erro ≤ 2% (respostas 5xx ou timeout), medidos em teste de carga de 10 minutos em ambiente de homologação. | Performance | CP1, CP3, CP5 |
| <span id="rnf07"></span>RNF07 | Disponibilidade do sistema | A plataforma deve ter disponibilidade mínima de 98% nas áreas de acesso público, aferida por monitoramento externo com verificação a cada 5 minutos | Confiabilidade | Transversal (Todas as CPs) |
| <span id="rnf08"></span>RNF08 | Proteção de dados pessoais e credenciais (LGPD) |O sistema deve proteger os dados pessoais de voluntários e clientes (como CPF e informações de contato), transmitindo-os exclusivamente por conexão criptografada (HTTPS/TLS), e armazenar senhas utilizando o hash, por meio de algoritmo adequado para senhas (bcrypt ou Argon2).| Segurança |CP3, CP4, CP6 |
| <span id="rnf09"></span>RNF09 | Usabilidade do formulário de triagem | O formulário de triagem inicial deve poder ser concluído, sem criação de conta, por pelo menos 90% dos usuários com baixa familiaridade digital em teste de usabilidade com o protótipo, considerando concluído quando o usuário chega ao encaminhamento adequado sem ajuda externa. | Usabilidade | CP2 |
| <span id="rnf10"></span>RNF10 | Compatibilidade entre navegadores | O sistema deve apresentar paridade funcional e visual, sem quebras de layout, nas duas últimas versões estáveis do Chrome, Firefox, Safari e Edge. | Suportabilidade | Transversal (Todas as CPs) |
